# Regnum: план модов и интеграции

Дата: 2 октября 2026. Для владельца проекта, Claude и основного Codex.

## Проект и цель

Regnum — мод Minecraft 1.21.1 / NeoForge 21.1.x (`mod_id=regnum`). Общий репозиторий: [Alkim0r/mode](https://github.com/Alkim0r/mode), ветка `main` (сейчас виден как публичный). JAR-справочники лежат только локально в `_refs/` и исключены из Git.

Цель — не переписывать с нуля готовых боссов и мир. Сначала проверяем целые моды в отдельном локальном профиле Minecraft; затем связываем их с сюжетной кампанией Regnum тонким compatibility-слоем. Экономика королевств, города, армия, технологии, дипломатия, Create/Aeronautics и сетевые правила остаются системами Regnum.

## Решения, уже принятые

1. **Сначала запуск целых модов как зависимостей.** Оригинальные JAR остаются нетронутыми. Не копировать их модели, текстуры, звуки или код в Regnum автоматически. Переносить отдельные фрагменты исходников можно лишь после технической проверки и соблюдения условий лицензии.
2. **Опциональная совместимость.** Базовый Regnum должен запускаться без модов-спутников. Не ссылаться на классы стороннего мода в обязательном коде; проверять загрузку по mod id и подключать адаптер только при наличии мода.
3. **Разделить профили.** Отдельно проверять боссов/данжи, Create и мирогенерацию. Не складывать все JAR в одну сборку, пока не установлены обязательные зависимости и конфликты.
4. **Беречь слабые ПК.** Lite отключает необязательные визуальные эффекты, тяжёлые звуковые моды и избыточный декор. Не включать одновременно конкурирующие рендереры и боевые системы. Worldgen испытывать на новом тестовом мире; моды генерации должны совпадать на сервере и у игроков.
5. **Не выдавать наличие файла за интеграцию.** JAR в `_refs/` — скачанный ориентир, пока профиль с ним не запустился и проверка не пройдена.
6. **Финальный модпак/JAR не выпускать до согласования владельца.** Сначала проверяем local profile и совместную игру.

### Общий интерфейс интеграций

- Внешние боссы/структуры остаются в companion-модах. Первый мост использует их registry ID и публичные NeoForge-события, не прямую ссылку на классы и не меняет поведение источника.
- Награда, квестовый журнал и репутация остаются в Regnum. До кода согласовать с Claude формат события/вызова, повторные убийства, начисление группе игроков и недоступный/выгруженный мир.
- Create и Aeronautics подключаются опционально и проверяются раздельно. Aeronautics JAR сейчас отсутствует; поддержку нельзя называть проверенной.
- Основной Codex может подготовить ограниченный dependency gate; установка файлов в игровые `mods/` и проверка сочетаний — отдельный шаг после закрытия зависимостей. Внутренний helper `lite_performance_codex` остановлен по просьбе владельца и больше не получает задачи.
- Никто не выпускает общий jar/modpack и не публикует утверждение «совместимо», пока конкретный профиль не прошёл тесты и владелец не одобрил выпуск.

## Однодневный план: варианты на согласование

Полная интеграция всех модов, боссов, данжей, Create/Aeronautics, оптимизация и визуальная полировка не являются задачей на один день. Чтобы получить законченный проверяемый результат за одну параллельную рабочую смену, предлагаю ограничить общий объём примерно **6–8 часами работы по каждому владельцу** и выбрать один из вариантов. Это предварительная оценка основного Codex; Claude ещё должен подтвердить/скорректировать свою долю.

**Вариант A — подготовить реальную интеграцию из модов (рекомендую, если приоритет — подключение внешних модов).** Основной Codex за 3–4 часа делает ограниченный dependency gate для 10 выбранных JAR из `regnum/_refs/`: обязательные/необязательные mod IDs, несовместимости, точный профиль-кандидат и список блокеров. Параллельно Claude за согласованное время определяет серверный hook и контракт для одного выбранного босса → одного квеста/награды, добавляет тест без обязательной ссылки на внешний класс. Если после аудита все зависимости есть и обе части укладываются в день, можно добавить bridge; иначе итог дня — проверяемая таблица, контракт и один обоснованный кандидат, а не заявление о runtime-интеграции.

**Вариант B — заметный внутриигровой результат за день.** Claude закрывает один небольшой server issue из текущего BOARD (например, idle brood C11, если оценка позволяет), основной Codex делает один end-to-end визуальный QA-срез Королевы и только её выводка (походка/атака/реакция на цель) и исправляет не более 1–2 подтверждённых проблем. Интеграцию внешних модов откладываем до dependency gate.

**Предложение основного Codex:** выбрать A, потому что владелец прямо просит использовать внешние моды; ограничить ожидание результата дня compatibility gate + однозначный следующий кандидат, а не обещать «все моды уже встроены». Если анализ покажет отсутствие реалистичного кандидата или runtime-зависимости не помещаются в смену, немедленно перейти к B. Я оцениваю A как 3–4 часа аудита плюс параллельная оценка/контракт Claude; это предварительно и требует ответа Claude.

**Вопросы участникам для выбора:** реально ли закрыть их долю за одну смену; какой конкретный пункт из A или B они выбирают; что надо выкинуть, чтобы уложиться; какие тесты обязательны; каков главный риск? Пока ответов нет, выбор остаётся предложением, а не утверждённой сменой задач.

## Как именно связывать системы

### Внешний босс → квест Regnum

Предпочтительная схема: optional event-adapter в Regnum слушает событие смерти сущности, проверяет registry id из данных/конфига и передаёт результат в серверный API `story/Quests`. Награда, репутация и запись журнала принадлежат Regnum. Не импортировать класс босса и не менять его поведение на первом этапе. До реализации согласовать с Claude точку входа в `story/*`, права на награду, повторное убийство, multiplayer-credit и offline/loaded chunk случаи.

### Структура мода → экспедиция/цель

На первом этапе структура остаётся в своём моде и генерируется его worldgen. Regnum может дать экспедиционный квест, подсказку/locate и награду за достижение/победу. Проверить структуру и квесты на новом мире; не предполагать конкретный layout или entity id без реестра и теста.

### Create / Aeronautics → королевство

Create-механизмы должны питать уже существующую механику технологического преимущества (город/производство/осада) с явными пределами и дешёвой проверкой чанков. Aeronautics должен подключаться отдельной soft-веткой: воздушный командир, экипаж, снабжение/разведка и взаимодействие с городом — без зависимости базовой армии от самолёта. Точные события/attachment API выбрать только после наличия JAR и проверки совместимой версии. Create Big Cannons отдельно проверить как средство осады, не считать частью Aeronautics.

### Модели и анимации → визуал Regnum

Сначала оставить модели и анимации внутри исходного companion-мода. Для собственных Regnum-моделей переносить только алгоритмы/идеи с отдельной записью источника и лицензии; внешний runtime API не добавлять как обязательный, пока это не даёт проверяемого выигрыша. Персонажи и юниты должны анимироваться по серверному состоянию атаки/уклонения, а не только по клиентскому таймеру.

## Порядок проверки

1. Открыть GitHub-репозиторий и, если нужно писать в него, согласовать с владельцем права и ветку; скачать `main`, прочитать `AGENTS.md`, `coord/PROTOCOL.md`, `coord/BOARD.md` и `coord/LOCKS.md`.
2. Проверить обязательные зависимости и версии в `META-INF/neoforge.mods.toml` каждого JAR. Отсутствующую зависимость не заменять догадкой.
3. Составить изолированные профили: (а) один мод боссов за запуск, (б) Create + Big Cannons с зависимостями, (в) worldgen на свежем тестовом мире, (г) лёгкие клиентские оптимизации по одной.
4. Запустить dedicated-server smoke test, затем клиентский тест; записать crash log, модлист и результаты. Только после этого объявлять сочетание совместимым.
5. Зафиксировать мосты по одному: босс/квест, структура/экспедиция, Create/экономика, Aeronautics/воздух. После каждого — selftest и multiplayer-сценарий.
6. Поддерживать два игровых пресета: **Full** для полного визуального набора и **Lite** для слабого железа. Core/серверные правила и сохранения остаются общими; не удалять обязательные worldgen/data-моды из уже созданного мира.

Пока `coord/BUILD.lock` занят, сборку не запускать. Изменения серверной логики `kingdom/`, `story/` и `core/SelfTest.java` предварительно согласовывать с владельцем этой полосы через `coord/INBOX_claude.md`.

## Не утверждать как уже сделанное

- Ни один внешний босс-мод ещё не подтверждён совместным запуском с Regnum.
- Aeronautics JAR отсутствует; фактическая связка Create + Aeronautics пока не проверена.
- Созданная ветка GitHub `main` сейчас может отставать от рабочей копии: передача незакоммиченных изменений в remote не предполагается.
- Наличие отдельного мода в `_refs` не означает, что его боссы, структуры или ассеты уже «вмонтированы» в Regnum.
