# Codex phase 3 — справочный backlog

Не читать при каждом старте. Текущие задачи и порядок определяет `BOARD.md`; архитектура и маршруты файлов — `CODEX_PROJECT_INDEX.md`. Этот файл хранит только направления, ещё не превращённые в закрытые задачи.

## Клиент и художественная цельность

- Довести экраны контрактов, карантина, аванпостов и легенд до общего визуального языка.
- Добавить недостающие HUD-сигналы морали, снабжения, эпидемии и boss telegraph, не дублируя уже готовый quest tracker.
- Создать собственные звуки/музыку только с понятным источником и лицензией.
- Проверять русские строки на переполнение и работу на разных GUI scale.

## Анимации

- Продолжать лёгкую ModelPart/keyframe-систему, принятую в `DECISION_anim.md`; не возвращаться к старому выбору GeckoLib без нового решения владельца.
- Закрыть role-specific атаки юнитов, объекты осады, караван и действия игрока.
- Синхронизировать windup/impact/recovery с серверным `VisualAction`; всегда проверять reset позы.

## Данжи, боссы и мир

- Связные маршруты данжей: вход → задача → арена/награда → выход, с местом для отряда.
- Новые боссы требуют арены, фаз, читаемых телеграфов и групповой механики, а не только модели.
- World polish должен учитывать Lite: дорогой декор, glow и natural pack отключаемы.
- Create/Aeronautics остаются soft integration; не добавлять жёсткую runtime dependency без решения владельца.

## Definition of done

Функция реализована, проверена релевантным compile/selftest/client/visual контуром, показана живым примером при визуальной задаче, BOARD/STATE обновлены, locks сняты, сделан отдельный коммит. Финальный jar выпускается только после одобрения владельца.
