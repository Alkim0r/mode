# Анимации Regnum: решение для текущей ветки

Дата: 02.10.2026. Автор: Codex. Статус: техническое решение для текущей реализации; не является подтверждением владельца на добавление внешних зависимостей.

## Решение

Для текущей версии продолжаем лёгкую собственную систему поверх Minecraft `ModelPart` и существующего `SoldierPoseAnimator`. GeckoLib не добавляется как обязательная зависимость. Player Animator и Better Combat остаются возможными optional-интеграциями после проверки точных версий и наличия библиотек; пока интеграций нет.

## Почему

- В проекте уже зарегистрированы собственные модели/рендеры (`RegnumHumanoidModel`, `RegionBossRenderers`) и процедурный аниматор солдат. Это позволяет добавлять боевые позы без миграции всех сущностей на другую модельную основу.
- В `_refs` и `libs` не найдено jar GeckoLib, Player Animator или Better Combat; текущий `build.gradle` их не объявляет. Без проверенной версии нельзя безопасно закрепить API, загрузку и клиент/серверную конфигурацию.
- Собственная система лучше соответствует требованию облегчённого режима и не делает запуск базового мода зависимым от ещё не проверенной библиотеки.
- Рекомендация Claude о GeckoLib остаётся сильным вариантом для полноценной временной шкалы анимаций боссов и крупных существ, но требует отдельного технического прогона и решения владельца о зависимости.

## Границы реализации

1. В текущей ветке развивать процедурные позы и небольшие клипы для существующих моделей; не менять сетевые/серверные API ради декоративных движений.
2. Боевые действия боссов привязывать к реальному `Telegraph` windup/impact, а не к произвольным клиентским таймерам. Если клиенту не хватает состояния фазы, сначала согласовать минимальный payload с владельцем серверной логики.
3. Внешнюю интеграцию разрешать только после проверки версий NeoForge 1.21.1, серверного dedicated launch, отсутствующего optional-mod fallback и поведения при обновлении/переподключении.
4. Пересмотреть решение, когда подтверждённый GeckoLib jar появится в `_refs` и отдельный тест покажет выигрыш для боссов, который оправдывает зависимость или адаптер.

## Проверка

Это архитектурное решение не проверено сборкой или в игре. Глобальный слот сборки на момент записи занят `claude council`; библиотек в локальных `_refs`/`libs` нет.

Никакой runtime зависимости LLibrary не требуется.
